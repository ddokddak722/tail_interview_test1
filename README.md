# 꼬리물기 면접 모드 - 배포 안내

준규님, 안녕하세요! 이 문서는 개발/코딩 지식이 없어도 따라 하실 수 있도록,
처음부터 끝까지 순서대로 정리한 배포 안내문이에요. 천천히, 순서대로만
따라오시면 됩니다.

## 1. 이게 뭔가요?

기존 "면접관 하트어택" 아티팩트 안에 있던 두 가지 모드 중 "🔥 꼬리물기 면접
모드"만 따로 떼어내서, 독립된 웹사이트로 새로 만든 거예요. (다른 모드인
"면접관 마음 맞추기"는 기존 아티팩트에 그대로 남아있고 건드리지 않았어요.)

**이제는 서버(백엔드)가 전혀 필요 없어요.** 예전 버전은 준규님이 관리하는
작은 서버가 구글 Gemini API 키 하나를 공유해서 모든 참가자의 요청을
대신 처리하는 방식이었는데, 참가자가 많아지면(최대 30명 정도) 구글의
무료 요금제 한도(분당 15회)를 다 같이 나눠 써야 해서 병목이 생길 수 있는
구조였어요.

그래서 이번에는 방식을 바꿨어요: **참가자 각자가 자신의 구글 계정으로
무료 Gemini API 키를 직접 발급받아서, 사이트에 처음 접속했을 때 한 번만
붙여넣어요.** 그 이후로는 참가자의 브라우저가 구글 서버에 직접 요청을
보내고, 각자 독립된 무료 사용량(분당 15회, 하루 1,500회)을 쓰기 때문에
다른 참가자와 한도를 나눠 쓸 일이 없어요. 신용카드 등록도 필요 없고,
무료 한도를 넘으면 그냥 에러가 날 뿐 자동으로 돈이 청구되지 않아요
(청구가 되려면 별도로 결제 수단을 등록하는 절차를 거쳐야 해요).

정리하면, 이제 이 프로젝트는 **순수한 정적 웹사이트(HTML/CSS/JS/이미지
파일)**예요. 서버도, 환경 변수도, 준규님이 관리해야 할 API 키도 없어요.
그래서 배포 방법도 훨씬 간단해졌어요 (GitHub Pages라는 무료 서비스
하나면 충분해요).

전체 과정은 대략 10~15분 정도 걸리고, 아래 3단계로 이루어져 있어요.

1. GitHub 계정 만들기
2. 이 폴더를 GitHub에 올리기
3. GitHub Pages 켜서 사이트 주소 받기

---

## 2. GitHub 계정 만들기 (무료)

1. 브라우저에서 https://github.com 접속
2. 오른쪽 위 **Sign up** 버튼 클릭
3. 이메일, 비밀번호, 아이디(username)를 입력하고 안내에 따라 가입 완료
   (이메일 인증 코드가 오면 입력해주세요)
4. 가입이 끝나면 GitHub 첫 화면(대시보드)이 보이면 성공이에요.

이미 GitHub 계정이 있으시면 (이전에 만드셨다면) 이 단계는 건너뛰고
로그인만 해주세요.

---

## 3. 이 폴더를 GitHub 저장소로 올리기

git 명령어를 몰라도 되는, 웹사이트에서 드래그 앤 드롭으로 올리는 가장 쉬운
방법을 안내할게요.

1. GitHub 로그인 상태에서 오른쪽 위 **+** 버튼 → **New repository** 클릭
2. **Repository name**에 원하는 이름 입력 (예: `tail-interview-site`)
3. **Public**(공개)을 선택해주세요. GitHub Pages 무료 기능은 Public
   저장소에서 가장 간단하게 동작해요. (이 사이트에는 참가자 개인정보나
   비밀 값이 코드에 들어있지 않으니 공개해도 괜찮아요 — 참가자별 API
   키는 각자의 브라우저에만 저장되고 이 저장소에는 절대 올라가지
   않아요.)
4. 다른 옵션(README 추가 등)은 그대로 두고 **Create repository** 클릭
5. 저장소가 만들어지면 "Quick setup" 화면이 나와요. 거기서
   **uploading an existing file** 이라는 파란 글씨 링크를 클릭하세요.
6. 이 `tail-interview-site` 폴더 **안에 있는 모든 파일과 폴더**
   (index.html, style.css, script.js, images 폴더, .gitignore, README.md)를
   통째로 선택해서 화면에 끌어다 놓으세요(드래그 앤 드롭). 폴더째로 끌어다
   놓아도 되고, 파일 탐색기에서 "Choose your files" 버튼으로 선택해도 돼요.
7. 아래로 스크롤해서 **Commit changes** 버튼 클릭 → 업로드 완료

이제 GitHub 저장소 화면에서 index.html, script.js 등 파일들이 다 보이면
성공이에요.

## 4. GitHub Pages 켜서 사이트 주소 받기

1. 방금 만든 저장소 화면 위쪽 탭에서 **Settings** 클릭
2. 왼쪽 메뉴에서 **Pages** 클릭
3. **Build and deployment** 항목에서:
   - **Source**: **Deploy from a branch** 선택
   - **Branch**: **main** 선택, 옆의 폴더는 **/ (root)** 선택
   - **Save** 클릭
4. 약 1분 정도 기다리면 같은 페이지 위쪽에 초록색으로
   "Your site is live at `https://<아이디>.github.io/<저장소이름>/`"
   같은 문구와 함께 주소가 나타나요. (새로고침을 몇 번 해봐도 좋아요.)
5. 그 주소를 클릭해서 들어가보면 "꼬리물기 면접 모드" 첫 화면이 바로
   보이면 성공이에요.

**참고**: 이미 이전 라운드에서 Vercel 프로젝트를 만들어두셨다면, 그건 그대로
두셔도 괜찮아요. 이제 서버 기능이 없는 순수 정적 사이트라서 Vercel도 여전히
문제없이 잘 동작해요 — 다만 서버/환경 변수가 필요 없어진 지금은 GitHub
Pages 쪽이 더 간단해서 이 문서는 그 방법을 기준으로 안내드려요. 굳이
옮기실 필요는 없고, 편하신 쪽을 쓰시면 돼요.

## 5. 참가자 안내 (참가자에게 링크 보낼 때 이렇게 안내해주세요)

아래 문구를 그대로 복사해서 참가자들에게 공유하시면 돼요.

> 이 링크로 처음 들어가시면, 먼저 무료 Gemini API 키를 발급받아 붙여넣는
> 화면이 나와요. 구글 계정으로 로그인해서 "Create API key" 버튼만 누르면
> 되고, 신용카드 등록이나 결제 정보 입력은 전혀 필요 없어요 (약 1분
> 소요). 한 번 등록하면 그 이후로는 내 브라우저에 저장되어서 다음에
> 다시 들어올 때는 이 과정을 반복하지 않아도 돼요. (단, 다른 브라우저나
> 다른 기기로 접속하면 다시 등록해야 해요.)
>
> 그다음 진행자에게 안내받은 해제 코드(`tail2026`)를 입력하면 면접
> 모드를 바로 시작할 수 있어요.

## 6. 문제가 생겼을 때

뭔가 안 될 때는 아래 정보를 캡처(스크린샷)해서 Claude에게 보여주시면
훨씬 빨리 원인을 찾을 수 있어요.

1. **화면에 뜨는 에러 메시지 전체** (빨간 글씨 안내 문구 등) 스크린샷.
   특히 아래 메시지들은 각각 원인이 달라요:
   - "저장된 API 키가 없어요..." → 참가자가 아직 API 키를 등록하지
     않은 상태예요. 화면에 안내된 대로 키 등록 화면으로 진행하면 돼요.
   - "저장된 API 키가 유효하지 않아요..." → 참가자가 입력한 키가
     잘못되었거나, 구글 AI Studio에서 키가 삭제/만료된 경우예요.
     화면에 뜨는 "🔑 API 키 변경하기" 버튼(또는 화면 위쪽의
     "🔑 API 키 변경" 버튼)을 눌러서 키를 다시 발급받아 등록하면 돼요.
   - "오늘 개인 사용 한도를 초과했어요..." → 그 참가자 개인의 하루
     무료 사용량(1,500회)을 다 쓴 경우예요. 다음 날 다시 시도하면
     정상적으로 동작해요. (보통 면접 세션 한 번에 10~20회 정도만
     쓰기 때문에 실제로 이 메시지를 보는 일은 드물어요.)
   - "입력하신 내용이 안전 정책에 걸려..." → 구글의 콘텐츠 안전 정책에
     걸린 경우예요. 자기소개서 내용 중 일부를 조금 수정해서 다시
     시도하면 대부분 해결돼요.
2. 브라우저 개발자 도구를 열 수 있다면 (크롬 기준: 화면에서 마우스 오른쪽
   클릭 → 검사 → 상단의 **Console** 탭) 거기 빨간 글씨로 뜨는 에러 메시지
   스크린샷 — 이게 없어도 괜찮으니 부담 갖지 않으셔도 돼요.
3. 언제, 어떤 버튼을 눌렀을 때 문제가 생겼는지 한 줄 설명
   (예: "API 키 입력하고 저장 버튼 눌렀더니 흰 화면만 나와요")

이 3가지만 있으면 대부분의 문제는 금방 해결할 수 있어요.

해제 코드를 바꾸고 싶으시면 Claude에게 말씀해주시면 `script.js`의
`TAIL_UNLOCK_CODE` 값을 바꿔드릴 수 있어요. 결과 제출용 구글 폼 주소도
기존과 동일하게 그대로 들어있고, 새 폼을 쓰고 싶으시면 `script.js` 안의
`RESULT_FORM_CONFIG` 값을 바꾸면 되는데, 이것도 어려우시면 Claude에게
요청해주세요.

## 참고: 알려진 미확인 사항 (열어보시기 전에 한 번 확인해주세요)

이 프로젝트를 만든 환경에서는 실제 구글 서버에 인터넷 연결을 할 수 없어서,
Gemini API 호출 자체를 실제 키로 테스트해보지는 못했어요 (대신 가짜
응답으로 전체 화면 흐름만 꼼꼼히 확인했어요). 그래서 아래 한 가지는 처음
실제로 써보실 때 확인이 필요해요.

- 코드에 적어둔 모델 이름 `gemini-2.5-flash`가 이 안내문을 읽으시는
  시점에도 여전히 유효한 무료 모델 이름인지는 구글 쪽 정책이 바뀔 수도
  있어서 100% 보장은 못 드려요. 만약 실제 키를 등록했는데도 "AI 연결에
  문제가 발생했다"는 메시지가 계속 뜨면, 브라우저 개발자 도구의
  **Console** 또는 **Network** 탭에서 에러 메시지를 확인해서 Claude에게
  보여주세요. 모델 이름을 최신 것으로 바꿔드리면 돼요.
